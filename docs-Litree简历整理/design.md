### 第 8 页：项目一｜Litree 智慧水务云平台（Agent 工程化）

本页作为一个完整实践项目呈现，不写成“使用过 AI 工具”的能力清单。

- **项目目标**：基于 AgentScope Java 2.0 的 `HarnessAgent/ReActAgent` 与 Agent Runtime 能力，构建适配 Litree Java 21 + Spring Cloud 微服务体系的企业级 Agent 工程底座，支持长任务、工具调用、上下文恢复和多 Agent 协作。
- **框架适配**：对 AgentScope 的 Model、Toolkit、Memory、Session、Workspace 和 Event 抽象进行 Litree 封装，接入 Nacos 配置、统一认证、租户上下文、系统日志与 Spring 依赖注入。
- **业务工具化**：将水站、设备、物模型、告警、工单、GIS 管网和统计查询等领域能力封装为可控 Tool/MCP 服务，统一参数校验、结果结构、超时、重试和错误回传。
- **多租户与会话持久化**：按 tenant/user/agent/session 隔离运行上下文，基于 Redis/PostgreSQL 持久化会话、记忆与执行状态，支持微服务副本间的会话恢复。
- **权限与安全执行**：使用“允许/人工审批/拒绝”三态工具权限，对设备控制、数据修改和代码执行等高风险操作引入 HITL 确认与沙箱隔离，保留完整审计链路。
- **多 Agent 编排**：按规划、数据查询、业务分析、报告生成和结果审核拆分子 Agent，支持同步/后台任务委派、事件流转发和失败恢复。
- **数据智能体联动**：保留 Spring AI Alibaba Graph 在可控数据分析流程中的优势，编排意图识别、Schema 召回、NL2SQL、Planner、Python 生成/执行、人工反馈和报告生成；AgentScope 侧负责长任务 Harness、工具管理、会话与多 Agent 运行。
- **RAG 与知识增强**：整合 Elasticsearch Vector Store、文档切分、关键词 + 向量混合检索、业务知识库和上下文压缩，对水务专业术语与租户知识做权限隔离。
- **AI Coding 研发闭环**：将 Codex、Claude Code、Cursor、Trae 用于需求拆解、实现、测试、Review 和文档；以 `AGENTS.md + Skills + 三态任务目录` 固化研发流程，通过 GitLab CI 校验 Skill 结构和跨端同步。

本页技术关键词：AgentScope Java 2.0、HarnessAgent、ReAct、Toolkit、Middleware、HITL、Multi-Agent、Spring AI Alibaba Graph、RAG、MCP、Redis、PostgreSQL、Docker/Kubernetes Sandbox。

## 6. 网页数字展馆设计

### 6.1 定位与视觉方向

- 网页不是 PDF 的翻页器，也不是传统作品集首页，而是一座可部署的全屏 3D 简历展馆。
- 采用已确认的 `B｜电影级数字孪生`：以真实工业钢构、水工管道和混凝土材质建立可信空间，以青绿色水网光场表现运行数据，以安全橙强调入口、关键成果和交互状态。
- 首屏 Three.js 场景全屏无边框，不放在装饰性卡片或浏览器模型中。视觉原型中的白色外框仅属于评审工具，不进入最终网页。
- Agent 展厅可局部使用更高强度的赛博光效；其他展厅保持工业数字孪生风格，避免整站成为霓虹游戏界面。
- 不使用语音自我介绍、数字人、装饰性渐变球或纯氛围背景。主视觉由真实 3D 建筑、PBR 材质、灯光、水网装置和项目内容共同构成。

### 6.2 技术架构

- 前端采用 `Vite + React + TypeScript`。
- 3D 场景采用 `React Three Fiber / Three.js`；建筑、灯光、数据流和控制能力以精简的程序化实现完成，材质与灯光使用 Three.js 标准 PBR 管线，避免引入未使用的媒体、物理和后处理整包。
- 电影式入场和界面转场采用 `GSAP`。入场阶段由 GSAP 相机轨道接管，完成后切换为可阻尼的自由观察/行走控制，避免脚本镜头与用户输入抢占控制权。
- UI 图标统一使用 Lucide，界面文字、热点、迷你地图和降级页面使用语义化 HTML 覆盖在 WebGL 场景之上。
- 站点构建为纯静态资源，提供 `Dockerfile + Nginx` 部署方式；不依赖后端服务即可运行。

### 6.3 入场与探索流程

1. 首屏立即显示轻量启动界面和加载进度，不等待全部 3D 资源后才出现内容。
2. 核心资源就绪后进入 6-8 秒电影式入场：系统启动、穿越水网数据流、Litree 数字孪生核心开启、抵达中央馆。
3. `跳过动画` 始终可见并可用；用户操作后立即结束脚本镜头，不阻塞交互。
4. 入场完成后交还自由探索控制权，支持 WASD、鼠标观察和展馆热点点击。
5. 迷你地图、项目索引和“返回中央馆”持续可达，避免招聘方在自由探索中遗漏核心内容。
6. 每个展厅按照 `项目背景 → 本人角色 → 核心实现 → 技术难点 → 落地结果 → 技术栈` 展开，信息内容与 PDF 对齐。

### 6.4 空间信息架构

- **入口大厅**：姓名、目标岗位、近 6 年 Java 后端经验、联系方式和 PDF 下载。
- **中央馆**：Litree 智慧水务云平台总览，突出国内外 `10,000+ 水站` 的平台规模以及本人高级 Java 开发工程师定位。

- **AIoT 协议展厅**：有人云接入及团队多协议平台能力，展示协议数据进入统一物模型的处理链路。
- **GIS/DMA 展厅**：管点、管线、设备、拓扑、DMA 分区与流量/压力监控。
- **OA/HR 展厅**：组织人员、站点同步、统一登录、考勤、绩效和 HR 业务协同。

### 6.5 组件与数据边界

- `resume-data`：唯一履历事实源，包含个人信息、工作经历、项目、专题、技术栈和已确认量化信息；网页、DOCX 和 PDF 均从该数据源读取或生成。
- `museum-shell`：负责加载状态、移动端提示、全局导航、PDF 下载、联系方式和无障碍入口。
- `scene-runtime`：负责渲染器、相机、灯光、后期处理、性能档位和 WebGL 生命周期。
- `intro-sequence`：只负责启动到中央馆的脚本镜头，可跳过、可中断，不持有简历内容状态。
- `navigation-runtime`：负责自由探索、热点、展厅切换、当前位置和返回路径。
- `exhibit-content`：负责项目内容面板和深度阅读，不直接操作 3D 相机。
- `fallback-resume`：负责移动端、WebGL 不可用和减少动态模式下的纵向简历体验。

### 6.6 加载、错误与性能策略

- 首屏只加载启动界面、核心字体和中央馆低模资源；侧馆模型、纹理和特效按进入意图懒加载。
- GLTF 模型采用 Draco/Meshopt 压缩，纹理使用 WebP/AVIF 或 KTX2，明确尺寸并限制纹理分辨率，避免加载原始大模型。
- 渲染器根据设备能力选择高、中、低档：控制像素比、阴影、后期 Bloom、粒子数量和反射质量。
- 加载超过 300ms 显示明确进度；单个展厅资源失败时保留文字内容并显示可重试状态，不让整个页面白屏。
- WebGL 初始化失败时自动进入 2D 纵向简历，并保留项目导航、联系方式和 PDF 下载。
- 支持 `prefers-reduced-motion`：关闭电影入场、镜头漂移、粒子和扫描动画，直接显示稳定的中央馆或 2D 简历。

### 6.7 手机端策略

- 手机首次进入时显示：`建议使用电脑端浏览，以获得完整 3D 展馆体验`。
- 提示不阻断访问，确认后进入轻量纵向简历；默认不加载完整展馆模型、实时阴影和重型后期处理。
- 手机页面保留项目索引、Litree 六个专题、WeLink、森格、联系方式与 PDF 下载，触控目标不小于 44px，无横向滚动。

### 6.8 PDF 与网页同步

- 10 页 PDF 继续采用正式投递排版：白底、可检索文本、克制的蓝绿色强调，不照搬深色 3D 展馆。
- 网页与 PDF 共享事实和内容结构，但允许不同表现：网页强调空间叙事与交互，PDF 强调 ATS、打印和快速扫描。
- PDF 下载按钮使用最终生成文件，不提供临时占位链接；联系方式和项目数字必须与网页逐项一致。

### 6.9 验证标准

- 桌面端至少检查 `1440×900`、`1920×1080`；移动端至少检查 `375×812` 和横屏。
- 使用浏览器截图和 Canvas 像素检查确认 Three.js 场景非空、构图完整、动画运行且无 UI 重叠。
- 验证键盘焦点、跳过动画、热点替代导航、减少动态、WebGL 降级和资源失败恢复。
- 检查首屏无布局跳动、导航不遮挡内容、按钮与长文本在各视口不溢出。
- PDF 必须恰好 10 页、文本可提取，并逐页渲染检查截断、重叠、乱码、页码和页眉页脚。
